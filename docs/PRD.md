## CogniLabel V1.0 产品需求文档（最终版）

### 一、产品概述

#### 1.1 产品名称

CogniLabel

#### 1.2 产品定位

面向生产流程的标签图片自动复核工具（本地运行）。

用于在标签打印前，对供应商提供的标签图片电子档进行自动识别与校验，减少人工核对工作量。

#### 1.3 核心目标

- 自动识别图片中的二维码/条形码
- 与 Excel 生产资料进行匹配
- 自动发现异常（错误 / 重复 / 未识别）
- 输出可供人工复核的结果

### 二、关键业务约束（已确认）

| 项目 | 结论 |
|---|---|
| 数据关系 | ✅ 一图 = 一个图片文件 = 一个设备 = Excel 一行（强制一一映射） |
| 主键逻辑 | ✅ 主键 = `SN`（来源于条码），且仅此一个主键 |
| 模板稳定性 | ✅ 同一项目布局一致 |
| ROI 坐标 | ✅ 使用相对比例坐标（自动适配不同分辨率） |
| 识别失败 | ✅ `SN` 识别失败则整图判 `UNREADABLE`；非主键字段失败仅记录字段级 `UNREADABLE` |
| Excel 字段 | ✅ 支持用户手动映射（按列名/表头） |
| 条码用途 | ✅ SN 来源（主识别键） |
| 二维码用途 | ✅ 承载组合信息（WiFi / URL 等） |
| 内容校验 | ✅ 仅做字符串比较（`Trim` 后比较）；❌ 不做 WiFi/URL 解析与格式规则 |
| 重复检测 | ✅ 当前批次（本次运行）内，仅对 `SN` 做重复检测 |
| 中断恢复 | ❌ 不支持 |
| 实时展示 | ✅ 简单进度 + 结果 |
| 错误图片导出 | ✅ 支持 |
| 输出策略 | ✅ 输出到时间戳文件夹，避免覆盖与混乱 |
| 最小追溯 | ✅ 报告内写入元信息（运行时间/项目/模板/Excel文件名/图片路径） |
| 日志/权限 | ❌ 不做（不做权限体系与独立日志系统） |

补充约束（前置校验 + 阻断执行）：

- Excel 主键（`SN`）必须唯一且非空；若发现重复或为空，直接中断本次审核，不进入图片识别阶段（见 4.2.3）

### 四、核心功能设计

#### 4.1 模板系统（固定版式）

##### 4.1.1 模板定义

模板用于定义：图片中各区域对应哪个字段（SN / QR 等）。

##### 4.1.2 模板结构

```json
{
  "TemplateName": "MIFI_A_V1",
  "Fields": [
    { "Name": "SN", "Type": "BARCODE", "X": 0.1, "Y": 0.7, "W": 0.6, "H": 0.15 },
    { "Name": "QR1", "Type": "QR", "X": 0.05, "Y": 0.05, "W": 0.4, "H": 0.4 }
  ]
}
```

坐标解释（相对比例 ROI）：

- `X`：图片宽度的占比（例如 `0.1` 表示从左侧 10% 处开始）
- `Y`：图片高度的占比
- `W`：宽度占比
- `H`：高度占比

ROI 边界处理（防止越界异常）：

- 当根据比例坐标（`X` / `Y` / `W` / `H`）换算为像素坐标后，若 ROI 超出图片边界：
  - 自动裁剪到图片有效范围（Clamp）
  - 不报错，不中断流程
  - 仍继续进行识别

说明：该策略用于兼容不同分辨率或轻微模板偏差，避免运行时异常。

##### 4.1.3 模板创建方式

- 导入示例图片
- 鼠标框选区域（ROI）
- 指定字段名称
- 保存模板

#### 4.2 Excel 导入 + 字段映射

##### 4.2.1 Excel 读取

- 支持：`.xlsx`

##### 4.2.2 字段映射（关键功能）

模板字段：

- 字段名支持自由命名（例如 `SN` / `QR1` / `WIFI` / `URL` 等）

Excel 映射规则：

- 按“列名（表头）”映射
- 映射配置可保存复用

数据读取规范（必须遵守）：

- Excel 全部按字符串读取
- `Trim` 前后空格后再参与比较
- 不做数值转换（避免科学计数法导致 SN 失真）

用户需配置：模板字段与 Excel 列的对应关系（示例）：

| 模板字段 | Excel 列 |
|---|---|
| SN | SN_CODE |
| QR1 | WIFI_INFO |

映射方式：

- 下拉选择 Excel 列名
- 保存配置（可复用）

##### 4.2.3 Excel 数据校验（预处理阶段，必须）

在审核开始前，系统需对 Excel 数据执行完整性检查（全表扫描）。该阶段为数据源校验，优先级高于所有识别与匹配逻辑。

检查项：

- 主键唯一性（`SN`）
- 主键完整性（`SN` 非空）

主键唯一性（`SN`）：

- 检查 `SN` 是否存在重复
- 若检测到重复 `SN`（Excel 主键重复）：
  - 弹出提示信息：“Excel 数据存在主键（SN）重复，请修复后再执行”
  - 直接中断本次审核流程
  - ❌ 不进入图片识别阶段

主键完整性（`SN` 非空）：

- 判定条件（写死）：
  - 单元格为空（`SN == null`）
  - 内容为空字符串（`SN == ""`）
  - `Trim` 后为空（`SN.Trim() == ""`，仅空格）
- 若存在上述情况：
  - 判定为数据源错误
  - 弹出提示信息：“Excel 数据存在空 SN（主键缺失），请修复后再执行”
  - 直接中断本次审核流程
  - ❌ 不进入图片识别阶段

Excel 预检查结果输出：

- 当 Excel 数据校验失败（如 SN 重复或为空）时，系统行为：
  - 中断审核流程
  - 弹出提示信息
  - 在界面中展示部分异常数据（默认前 20 条）
- 同时支持导出：`Excel预检查报告.xlsx`
  - 报告内容：
    - 重复 SN 列表（含出现次数）
    - 空 SN 记录（含所在行号）
      - 行号定义：Excel 真实行号（包含表头行），便于人工直接定位

说明（设计取舍）：

- SN 重复属于“数据源错误”，不是审核阶段问题
- 若在运行时处理，会引入匹配歧义与结果不可预测
- 前置校验可保证匹配逻辑简单（SN 唯一）、审核结果可预测、降低系统复杂度

#### 4.3 图片识别

##### 4.3.1 输入

- 文件夹批量导入
- 支持：`jpg / png / bmp`

##### 4.3.2 识别流程

读取图片 → 按模板裁剪 ROI → ZXing 识别 → 输出字符串

图片读取异常处理（统一归类）：

- 当图片出现以下情况：
  - 文件损坏
  - 格式不支持
  - 无法解码
- 统一处理为：
  - 判定为 `UNREADABLE`
  - 不新增额外异常类型（如 `FILE_ERROR` / `IO_ERROR`）

说明：避免异常类型膨胀，统一归类为识别失败。

##### 4.3.3 多码策略

- 每个字段对应一个区域
- V1 不做全图搜索

单 ROI 多码处理规则（ZXing 行为约束）：

- 当 ZXing 在同一个 ROI 中识别出多个码时：
  - 仅取第一个识别结果
  - 不进行多值比对
  - 不记录为异常

说明：V1 阶段不处理多码复杂场景，保证实现简单稳定。

#### 4.4 核心匹配逻辑

##### 4.4.1 匹配方式（关键）

通过 `SN`（条码）匹配 Excel 唯一行（锁死规则）：

- `SN` 是唯一主键
- ❌ 不允许使用二维码作为主键
- ❌ 不做主键切换 / 多主键

最终匹配规则（简化并锁死）：

- 识别出 `SN` → 在 Excel 中查找唯一一行 → 进行字段比对

不再需要（且明确不采用）：

- 多条匹配处理逻辑
- “取第一条 SN 继续执行”的分支
- 主键冲突类运行时异常类型

##### 4.4.2 校验逻辑

| 检查项 | 规则 |
|---|---|
| 存在性 | 识别值是否在 Excel 中 |
| 一致性 | `Trim` 后字符串完全相等（默认大小写敏感） |
| 唯一性 | 是否重复 |

Excel 字段空值参与比对规则（避免隐性歧义）：

- 当 Excel 中某字段存在但值为空时：
  - 该字段仍参与比对
  - 若与图片识别值不一致：判定为 `MISMATCH`

说明：避免因空值被忽略导致“误判为正确”。

#### 4.5 异常定义（非常关键）

异常类型：

1. `NOT_FOUND`（未匹配）：识别出的 SN 不在 Excel 中
2. `MISMATCH`（不一致）：字段值 ≠ Excel 值
3. `DUPLICATE`（重复）：同一 SN 出现多次
4. `UNREADABLE`（未识别）：码无法识别

异常类型收敛说明：

- 由于在审核前已做 Excel 主键唯一性校验（阻断执行），运行期不引入“Excel 主键重复/冲突”相关异常类型

`UNREADABLE` 分层定义：

- 主键 `SN` 识别失败：整图判 `UNREADABLE`，且
  - ❌ 不再匹配 Excel
  - ❌ 不尝试用 QR 反查
- 非主键字段识别失败：记录该字段 `UNREADABLE`，但仍继续用 `SN` 匹配并输出其他字段的差异

重复检测执行时机（避免顺序依赖）：

- 在所有图片识别完成后统一统计 `SN` 出现次数
- 当某个 `SN` 出现次数 > 1 时：
  - 标记为 `DUPLICATE`

说明：不在识别过程中实时判定，避免因处理顺序不同导致结果不一致。

#### 4.6 结果展示

表格结构（示例列）：

| 图片名 | SN | 状态 | 备注 |
|---|---|---|---|

UI 状态定义（收敛）：

- `PASS`
- `FAIL`

明细异常不在 UI 状态里“爆炸”，而是统一写入报告的异常明细（见 Sheet2）。

UI 行为：

- 实时刷新结果
- 显示当前进度

#### 4.7 报告输出

输出文件：`审核结果.xlsx`

报告导出异常处理（文件占用场景）：

- 当输出文件（如 `审核结果.xlsx`）被占用或写入失败时：
  - 提示用户关闭文件后重试
  - 不清空当前审核结果（结果保留在内存中）
  - 允许用户重新执行导出操作

说明：避免用户因文件占用导致数据丢失或需要重新审核。

Sheet 结构：

- Sheet0：元信息（最小追溯）
  - `运行时间` / `项目` / `模板` / `Excel文件名` / `图片路径`
- Sheet1：总览（示例字段）
  - `总数` / `PASS` / `FAIL`
- Sheet2：异常明细（多行展开）
  - `图片名` / `字段` / `问题类型` / `图片值` / `Excel值`
- Sheet3：重复数据（示例列）
  - `SN` / `次数`
- Sheet4：未识别（示例列）
  - `图片名`

#### 4.8 错误图片导出（推荐实现）

输出目录策略：

- 本次运行输出到：`output/<yyyy-MM-dd_HH-mm-ss>/`
- 报告文件：`output/<yyyy-MM-dd_HH-mm-ss>/审核结果.xlsx`

错误图片导出：

将异常图片复制到：`output/<yyyy-MM-dd_HH-mm-ss>/error/`

分类：

- `/duplicate/`
- `/not_found/`
- `/unreadable/`

### 六点一、并发处理策略（确定性规则）

系统采用多线程处理图片识别任务。

线程数规则：

- 线程数 = CPU 逻辑核心数 - 1
- 最小线程数 = 1

设计目的：

- 提升批量处理效率
- 避免占满 CPU 导致系统卡顿

V1 限制：

- 不提供用户手动配置并发数

### 十、V1 边界（必须控制）

#### 10.1 明确支持

- 支持固定版式标签图片
- 支持相同布局不同分辨率（通过比例 ROI）
- 支持一图一设备（强制一一映射）
- 支持 `SN` 作为唯一主键
- 支持字符串完全匹配校验（`Trim` 后比较）
- 支持当前批次重复检测（仅 `SN`）
- 支持异常图片导出

#### 10.2 明确不支持（V1）

数据层：

- ❌ 多图对应一设备
- ❌ 一图包含多个设备
- ❌ Excel 多主键匹配
- ❌ 使用 QR 作为主键

识别层：

- ❌ 全图自动找码
- ❌ OCR 文字识别
- ❌ 模板自动识别
- ❌ 图像畸变修正

校验层：

- ❌ WiFi 解析
- ❌ URL 解析
- ❌ 格式校验（IMEI 规则等）

逻辑层：

- ❌ 文件名参与匹配
- ❌ 历史重复检测
- ❌ 中断恢复

#### 10.3 假设条件（必须满足）

1. 同一项目图片布局一致
2. 图片清晰可识别
3. 每张图包含 SN 条码
4. Excel 数据唯一（SN 不重复）

#### 10.4 成功标准

- 自动筛出异常
- 人工处理 ≤ 10%

（以上边界用于锁死范围，防止 V1 膨胀。）

### 十一、总结（非常重要）

CogniLabel V1 的核心不是“识别全部正确”，而是：自动筛出问题，把人工从 100% 工作量降低到 10% 以内。
