# CogniLabel UI 设计规范（V1.1 - 审核系统版）

## 1. 设计目标

面向“批量标签审核”的操作场景，确保：

- 批处理效率优先（Batch First）
- 结果可读性优先（Result Readability）
- 异常识别优先（Error First）
- 最少操作路径（Minimal Flow）

## 2. 核心设计原则

### 2.1 原则

- 先执行，后分析（Run First）
- 结果驱动（Result Driven）
- 异常优先（Error First）
- 状态单一（Single State Source）

### 2.2 禁止事项

- ❌ 不允许左右查重布局（Split View）
- ❌ 不允许实时计算干扰操作
- ❌ 不允许多状态提示冲突
- ❌ 不允许默认 WPF 样式
- ❌ 不允许结果无高亮

## 3. 页面结构（强制）

### 3.1 标准布局（必须）

```text
+--------------------------------------------------+
| 配置区（可折叠）                                 |
| [项目][模板][Excel][图片]                        |
|                                                  |
| [字段映射]                                       |
|                                                  |
| [开始审核]（主按钮）                             |
+--------------------------------------------------+

+--------------------------------------------------+
| 状态区                                           |
| 进度条 + 当前处理信息 + 状态提示                 |
+--------------------------------------------------+

+--------------------------------------------------+
| 结果区（核心）                                   |
| DataGrid                                         |
+--------------------------------------------------+

+--------------------------------------------------+
| 操作区                                           |
| [导出报告]                                       |
+--------------------------------------------------+
```

### 3.2 区域说明

#### ① 配置区（Config Panel）

- **功能**
  - 项目选择
  - 模板选择
  - Excel 导入
  - 图片导入
  - 字段映射
- **强制约束**
  - 必须使用 Card
  - 审核开始后：配置区必须支持折叠（收缩为迷你状态或隐藏），以最大化 DataGrid 垂直显示空间

#### ② 状态区（Status Panel）

- **显示**
  - 当前阶段（Excel 校验 / 识别 / 匹配）
  - 进度条（%）
  - 当前处理图片名
  - 状态提示（InfoBar）
  - 实时统计汇总（Summary）：`[总数] | [通过数(绿)] | [异常数(红)]`

#### ③ 结果区（Result Panel）⭐核心

- DataGrid（必须占主要空间）
- 支持滚动
- 支持实时刷新

#### ④ 操作区（Action Panel）

- 导出报告
- 必须固定（Sticky）

### 6.2 行高亮规则（关键）

#### 6.2.1 异常高亮完整定义（强制）

| 类型 | 背景色 | 边框 | 前景色 |
| --- | --- | --- | --- |

### 6.3 样式约束

- 禁止默认 DataGrid
- 去除粗边框
- 行高统一
- 列对齐清晰

### 6.4 状态 vs 异常（必须，最关键）

问题本质：这是领域模型问题，不只是 UI 问题。必须明确“两层结构”，并写死映射规则。

#### 6.4.1 两层结构（强制）

第一层：UI 状态（行级）

```csharp
enum RowStatus
{
    PASS,
    FAIL
}
```

第二层：异常类型（细分）

```csharp
enum ErrorType
{
    NONE,
    NOT_FOUND,
    MISMATCH,
    DUPLICATE,
    UNREADABLE
}
```

#### 6.4.2 强制映射规则（必须写死）

| ErrorType | RowStatus |
| --- | --- |
| NONE | PASS |
| NOT_FOUND | FAIL |
| MISMATCH | FAIL |
| DUPLICATE | FAIL |
| UNREADABLE | FAIL |

关键结论：

- ❌ 不存在 WARN（V1 不引入）
- ❌ 不允许 UI 自行判断
- ✔ ViewModel 统一输出

## 7. 状态提示（InfoBar）

### 7.1 必须结构

- `[Icon] 文本提示`

### 7.2 示例

- 🔄 正在处理图片 23/100
- ⚠ Excel 存在重复 SN
- ✅ 审核完成
- ❌ 导出失败（文件占用）

### 7.3 严重级别（必须）

```csharp
enum InfoBarSeverity
{
    Info,
    Success,
    Warning,
    Error
}
```

### 7.4 映射规则（必须）

| 类型 | 颜色 | 是否自动消失 | 是否可关闭 |
| --- | --- | --- | --- |
| Info | 蓝 | 否 | 否 |
| Success | 绿 | ✔ 3 秒 | 否 |
| Warning | 橙 | 否 | ✔ |
| Error | 红 | 否 | ✔ |

### 7.5 行为规则（关键）

- ✔ 同一时间只显示一个 InfoBar
- ✔ 新消息覆盖旧消息
- ✔ Error 优先级最高（不可被低级覆盖）
- ✔ Error 级别消息不应被“简单覆盖”：若发生新的 Error，需合并/追加到错误列表，并保持可追溯
- ✔ 必须支持“查看详情”：点击 Error InfoBar 可打开错误日志列表（日志抽屉）或跳转至错误详情

## 13. Sticky 实现（必须）

问题本质：WPF 没有 CSS sticky。若不写清楚布局结构，必翻车。

### 13.1 标准实现（强制）

布局结构（唯一推荐）：

```xml
<Grid>
    <Grid.RowDefinitions>
        <RowDefinition Height="Auto"/>   <!-- 配置 -->
        <RowDefinition Height="Auto"/>   <!-- 状态 -->
        <RowDefinition Height="*"/>      <!-- 结果 -->
        <RowDefinition Height="Auto"/>   <!-- 操作区（固定） -->
    </Grid.RowDefinitions>
</Grid>
```

### 13.2 强制规则

- ❌ 操作区不得放入 ScrollViewer
- ✔ DataGrid 单独 Scroll
- ✔ 操作区永远可见

## 14. DataGrid 交互（必须）

问题本质：这是系统的核心操作区，不能模糊。

### 14.1 列宽策略（强制）

| 列 | 策略 |
| --- | --- |
| 图片名 | `1.5*`（填充，权重更高） |
| SN | 200（固定） |
| 状态 | 80（固定） |
| 异常类型 | 120（固定） |
| 备注 | `1*`（填充） |

### 14.2 对齐规则（强制）

| 类型 | 对齐 |
| --- | --- |
| 文本 | 左 |
| 状态 | 居中 |
| 数值 | 右 |

### 14.3 交互规则（强制）

| 功能 | 是否支持 |
| --- | --- |
| 排序 | ✔ 默认开启 |
| 筛选 | ❌（V1 不做） |
| 单元格复制 | ✔ |
| 行选中 | ✔ |
| 多选 | ✔（Ctrl） |

### 14.4 选中样式（强制）

- 背景：#DBEAFE
- 边框：#2563EB

### 14.5 审核验证交互（Quick Preview，必须）

目的（The “Why”）：用户需要“视觉验证”与“结果对照”，快速确认识别结果是否可信，以及异常原因。

强制交互：

- 选中 DataGrid 行时：必须同步刷新预览面板/浮层内容
- 双击 DataGrid 行时：必须打开大图预览（可新窗口/对话框/浮层），并显示对比详情

对比详情（必须包含）：

- 识别结果（OCR/解析结果）
- Excel 预期（期望值）
- 差异定位（Mismatch 字段高亮/逐字段对照）

## 15. 可访问性（建议升级为强制）

问题本质：大量浅色背景，若不控对比度会看不清。

### 15.1 最低标准

- 最小对比度 ≥ 4.5:1

### 15.2 推荐前景色规则

| 背景类型 | 前景色 |
| --- | --- |
| 浅红 | #991B1B |
| 浅橙 | #92400E |
| 浅黄 | #92400E |
| 默认 | #111827 |

## 16. 验收标准（DoD）

必须满足：

- ✔ 页面为上下结构
- ✔ 配置区为卡片
- ✔ 状态单一来源
- ✔ DataGrid 无默认样式
- ✔ 异常行必须高亮
- ✔ 主按钮清晰
- ✔ 有空状态提示
- ✔ UI 无 code-behind 控制
- ✔ 所有颜色来自资源
- ✔ 进度实时可见
- ✔ 支持配置区折叠以释放结果空间
- ✔ 状态区包含实时统计汇总（总数/通过/异常）
- ✔ DataGrid 行支持 Quick Preview（选中刷新预览、双击大图预览并可对比“识别 vs 预期”）
- ✔ 键盘快捷键可用（见 17 章）

## 17. 快捷键规范（Keyboard First）

原则：常用操作必须可通过键盘完成，减少鼠标来回移动。

| 快捷键 | 行为 |
| --- | --- |
| F5 | 开始审核 |
| Ctrl + E | 导出报告 |
| Up / Down | DataGrid 切换选中行，并同步刷新预览面板 |
