# CogniLabel V1 开发计划（总体技术方案）

> 约束：本文件仅包含设计与计划，**不包含任何实现代码**。  
> 关键约束：Clean Architecture 分层、WPF + MVVM、单一入口 `RunAudit`、`SemaphoreSlim` 并发、ZXing.Net、ClosedXML、无数据库、字符串集中管理、TDD。

---

## 1. 分层方案（Clean Architecture）

### 1.1 分层结构

- **Presentation（WPF / MVVM）**
  - 负责：页面布局、数据绑定、命令触发、进度/结果展示、预览交互（选中行刷新预览、双击大图预览）。
  - 禁止：业务规则、流程编排、ZXing/ClosedXML/文件 IO 直接调用。

- **Application（流程编排层）**
  - 负责：**唯一入口 `RunAudit`** 的 Pipeline 编排、并发控制、步骤间数据流转、错误/状态汇总、进度回调，调用 Core 与 Infrastructure。
  - 禁止：具体匹配/比对/重复检测规则（应在 Core）；具体 IO/第三方调用细节（应在 Infrastructure）。

- **Core（纯业务逻辑层，TDD 重点）**
  - 负责：模板 ROI 换算与 Clamp 规则、匹配/比对规则、重复检测、错误分类等**确定性业务逻辑**。
  - 强制：不依赖 UI/文件系统/第三方库；无状态、线程安全；纯函数/无副作用优先；可单测。

- **Infrastructure（外部依赖封装层）**
  - 负责：ZXing 识别封装、Excel 读取/导出（ClosedXML）、文件系统、图片加载/裁剪（图像解码等）。
  - 禁止：业务规则与流程控制。

---

### 1.2 新增：多码处理策略分层（分层边界修正）

为避免 Core 分层越界（Core 不应包含“多码取第一个”的策略），多码处理必须按以下分层职责固定：

- **Infrastructure**
  - 仅负责调用 ZXing 并返回**原始识别结果**：`List<string>`（可能为空/可能多条）
  - 不做“取第一个/选最优/去重”等业务决策

- **Application**
  - 负责把 Infrastructure 的 `List<string>` 归一化为“单值输入”：
    - **多码策略（锁死）**：若返回多条，仅取第一条作为该字段识别值
    - 若为空，则该字段识别值为空（交由后续错误分类规则处理）
  - 该策略属于流程编排层决策，不进入 Core

- **Core**
  - 仅接受“单值输入”（字段名 → 单个字符串或空）
  - Core 不关心 ZXing 是否多码，也不包含“多码取第一个”的选择逻辑
  - Core 只负责确定性规则：Trim 比较、错误分类、重复检测等

---

## 2. RunAudit 组织方式（分阶段 Pipeline，单一用例）

### 2.1 单一入口（V1 锁死）

- V1 所有业务执行必须从 `RunAudit(AuditRequest)` 进入。
- 不允许拆成多个用例（V1 禁止多用例/多入口）。

### 2.2 Pipeline 阶段（顺序锁死）

唯一主流程 `RunAudit` 的阶段（按 PRD）：

1. Excel 导入
2. Excel 预校验（SN 唯一 + 非空，失败即中断）
3. 模板加载
4. 图片批量识别（ROI + ZXing）
5. SN 匹配 Excel
6. 字段比对（Trim 后字符串完全比较）
7. 重复检测（仅 SN，且在识别完成后统一统计）
8. 汇总结果
9. 导出报告（Excel + 错误图片）

---

### 新增：【补丁 1】字段匹配与主键约束（防止 SN 逻辑漂移）

#### 新增：主键字段约束（强制）

- 模板中**必须存在且仅存在一个主键字段**：`SN`
- `SN` 字段必须参与（强制）：
  - 匹配（图片 → Excel）
  - 重复检测
  - `UNREADABLE` 判定（整图级）
- `SN` 字段不允许（强制）：
  - 缺失
  - 存在多个“主键字段”

#### 新增：字段分类（强制）

- 字段分为两类：
  - **主键字段**：`SN`
  - **普通字段**：其它模板字段（如 `QR1 / IMEI / MAC ...`）

#### 强制规则（锁死）

- 若 `SN` 未识别 → **整图 `UNREADABLE`**
- 若普通字段未识别 → **仅该字段 `UNREADABLE`**
  - 说明：普通字段 UNREADABLE 是否导致行级 FAIL，必须由既定“错误聚合规则”统一输出，禁止 UI 自行推断

---

### 新增：【补丁 2】SN 匹配策略（防止 Excel 行定位歧义）

#### 新增：SN 匹配规则（锁死）

- 匹配方式：**Trim 后字符串完全匹配**（大小写敏感，V1 不做忽略大小写）
- 匹配结果（锁死）：
  - 找不到 → `NOT_FOUND`
  - 找到唯一行 → 正常进入字段比对
  - 找到多行（理论上不应发生，但必须防御）→ 判定为 `DUPLICATE`（作为数据异常）

---

### 新增：【补丁 3】字段比对输入规范（防止隐式格式问题）

#### 新增：统一规范化规则（必须在 Core 前完成）

所有参与比对的字符串必须：

- `Trim`（仅前后空格）
- 保留原始大小写（V1 不做 `ToUpper/ToLower`）
- 不做任何格式转换（锁死）：
  - 不去除中间空格
  - 不格式化 `MAC / IMEI` 等

---

### 2.4 新增：Pipeline 中断机制（统一规范，禁止异常控制正常流程）

#### 2.4.1 统一结果结构（阶段结果 + 总结果）

- **新增：阶段结果 `StageResult`（概念结构）**
  - 用途：表达每一阶段的“是否成功/是否需要中断/对 UI 的提示信息/是否保留已有数据”
  - 约束：**禁止使用 Exception 作为正常流程的中断方式**
  - 系统错误（IO/解析失败等）可以通过异常产生，但必须在 Application 边界捕获并转换为 `StageResult` 的失败状态输出给 UI

- **新增：`AuditResult` 作为全流程结果容器**
  - 用途：承载当前运行的已产出数据（例如已读取的 Excel、已处理的图片结果、汇总统计等）以及导出所需信息
  - 规则：**中断不是丢弃数据**，而是返回一个“可展示/可追溯”的结果结构

---

#### 2.4.1.1 新增：StageResult / AuditResult 结构语义约束说明（强制）

> 目的：为实现阶段提供确定性结构，避免自由发挥导致对接发散。以下字段语义为契约：实现阶段**禁止**随意添加/删除/改名核心字段。

**新增：`StageResult`（阶段结果）必须包含的语义字段**

- **`IsSuccess`**
  - 语义：当前阶段是否执行成功
- **`ShouldStop`**
  - 语义：是否中断后续 Pipeline（关键字段）
  - 规则：当 `ShouldStop = true` 时，后续阶段不得继续执行
- **`Message`**
  - 语义：面向 UI 的提示信息（用户可见）
  - 约束：必须来自统一 `Strings`（禁止硬编码）
- **`ErrorType`（可选）**
  - 语义：与本阶段直接相关的统一错误类型（使用既定 `ErrorType` 枚举，如 `NOT_FOUND / MISMATCH / DUPLICATE / UNREADABLE`）
  - 约束：不得引入新的错误枚举体系；Excel 预校验类中断优先用 `Message` 给出业务提示
- **`Payload`（可选）**
  - 语义：阶段输出数据（例如 Excel 预检查结果、模板加载摘要、图片枚举统计等）
  - 约束：必须为结构化数据（禁止 `object/dynamic` 等非结构化类型）

**新增：`AuditResult`（全流程结果容器）必须包含的语义字段**

- **`Items`**
  - 语义：每张图片的处理结果集合（强制“一图一行”）
- **`Summary`**
  - 语义：汇总统计（至少：总数 / PASS / FAIL）
- **`Errors`**
  - 语义：异常明细集合（用于报告 Sheet2：字段、问题类型、图片值、Excel 值等）
- **`Meta`**
  - 语义：元信息（运行时间 / 输入路径 / 模板等最小追溯）

**补充：内存持有（强制）**

- 必须明确：`AuditResult` 在内存中长期持有，不依赖导出
- 导出只是持久化行为：导出失败不得要求用户重跑 `RunAudit`

---

### 新增：【补丁 7】AuditResult.Items 完整性（防止 UI 对不齐）

#### 新增：结果完整性约束（强制）

- 每一张输入图片 → 必须对应一条 `AuditResult.Items` 记录
  - 例外：仅当“取消策略”明确选择剔除未开始处理的图片时才允许缺失（且必须全局一致、可追溯）
- 禁止（强制）：
  - 因异常跳过记录
  - 丢失图片结果导致 UI / 导出对不齐

---

### 强化：DTO 不可变性（强制，防止并发污染与状态混乱）

适用范围：`AuditResult / ImageProcessResult / StageResult`（以及其内部嵌套的明细结构）。

必须遵守：

- **初始化后尽量不可变**：推荐只读属性或 init-only 语义（实现期选型，但必须达到“创建后不再被任意修改”的效果）
- **禁止跨线程修改同一实例**：并发阶段不得在多个线程上更新同一个 DTO 实例
- **并发阶段不得共享 DTO 实例引用**：每个并发任务必须产出独立的 `ImageProcessResult` 实例，不得共享引用并“补字段”

目的（强化）：

- 避免并发污染（竞态导致字段缺失/覆盖）
- 保证结果确定性（同输入多次运行输出一致）

---

### 新增：异常分级策略（非常关键，异常必须在 Application 边界收敛）

> 背景：禁止“异常做流程控制”不足以约束实现行为，还必须分级定义“业务错误/可恢复/不可恢复”并写死收敛策略，确保异常不穿透到 Presentation。

#### 新增：异常分级（强制）

1) **业务错误（Business Error）**

- 示例：Excel 预校验失败（SN 重复、SN 为空、SN 列映射缺失/表头找不到）
- 处理（强制）：
  - 转换为 `StageResult`（`IsSuccess = false`，必要时 `ShouldStop = true`）
  - **不抛异常**（禁止用 Exception 表达业务中断）

2) **可恢复系统错误（Recoverable）**

- 示例：单张图片读取/解码失败、ZXing 识别异常、单张图片 ROI 无效
- 处理（强制）：
  - 收敛为该图片（或字段）的 `UNREADABLE`
  - **不中断流程**（保证批处理鲁棒性）

3) **不可恢复系统错误（Fatal）**

- 示例：Excel 无法读取（无法打开/格式损坏等）、模板解析失败（JSON 不可读/字段缺失）、关键输入资源不可访问
- 处理（强制）：
  - 在 Application 边界捕获并收敛为 `StageResult`，并设置 `ShouldStop = true`
  - `Message` 必须来自 `Strings`（用于 UI 提示与追溯）

#### 强化：异常收敛强制规则（必须遵守）

- **禁止异常穿透到 Presentation**：Presentation 不得处理任何来自底层的异常类型/堆栈
- **所有异常必须在 Application 边界被收敛**：最终呈现为：
  - `StageResult`（中断/错误提示）
  - 或业务错误类型（例如 `UNREADABLE`）落到 `AuditResult.Items`

## 新增：UseCase 契约定义（RunAudit 接口约束，V1-Release Candidate）

> 目的：为 Cursor 后续“按阶段生成代码”提供确定性用例边界与参数契约，防止接口随意扩展造成层间耦合与结构发散。

### 新增：RunAudit 方法契约（概念级）

**输入（必须明确）**

- `AuditRequest`
- `IProgress<ProgressInfo>`（可选）
- `CancellationToken`（**必须新增**）

**输出（必须明确）**

- `AuditResult`

### 强化：RunAudit 强制约束（必须遵守）

- `RunAudit` 必须支持取消（CancellationToken）
- 取消时（强制）：
  - **不抛异常到 UI**
  - 返回“已执行部分结果”的 `AuditResult`
  - 必须在 `AuditResult.Meta` 中体现取消状态（语义必须存在，例如 `Cancelled` 标记；字段名实现期可定）

#### 2.4.2 哪些阶段允许中断（V1 锁死）

允许“中断并返回结果”的阶段（按优先级）：

1. **Excel 预校验阶段**（业务中断，阻断进入识别）
   - SN 重复 / SN 为空 / SN 列映射缺失或表头找不到（均为业务规则中断）
2. **模板加载阶段**（系统中断）
   - 模板 JSON 不可读/解析失败/字段缺失
3. **输入资源阶段**（系统/业务中断）
   - 图片目录为空或不存在、无支持格式文件（建议作为业务中断提示）

不应导致全流程中断的阶段：

- **单张图片处理失败**：应转为该图（或字段）`UNREADABLE`，其余图片继续（保证批处理鲁棒性）

#### 2.4.3 中断后系统行为（UI 提示 / 数据保留）

- UI 行为（Presentation）
  - 仅订阅 Application 输出的阶段结果（提示文案、严重级别、可操作项：例如导出预检查报告）
  - 不主动拉取流程状态，不自行推断中断原因

- 数据保留（Application）
  - Excel 预校验中断：保留“预检查失败详情”（前 N 条样例、重复统计、空值行号）用于 UI 展示与导出
  - 模板/IO 系统错误：返回可追溯错误信息（用于 InfoBar/错误详情），不继续后续阶段
  - **禁止**：中断时通过抛异常让 UI 自行解析（避免耦合与不可控）

### 2.3 阶段化输出（可评审、可测试）

- 每一阶段都有明确输入/输出 DTO（或纯模型），便于：
  - Core：规则级单元测试（纯逻辑、确定性）
  - Application：流程级集成测试（Happy path + 异常分支）

## 3. 并发模型（确定性并发）

### 3.1 并发范围

- **仅在“图片批量识别（单图处理）”阶段并发**。
- 匹配/比对/重复检测阶段应基于内存结果做确定性处理，避免顺序依赖。

### 3.2 并发机制（强制）

- `Task` + `SemaphoreSlim` 控制并发度
- `Task.WhenAll` 汇聚所有任务结果

### 3.3 并发数规则（强制）

- `maxConcurrency = max(1, CPU 逻辑核心数 - 1)`
- V1 不提供 UI 手动配置并发数入口（锁死规则，避免复杂度与不可控）。

### 3.4 确定性保障

- 单图处理应“无共享可变状态”，输出独立结果，再统一汇总。
- 重复检测必须在所有图片识别结束后统一统计（避免因处理顺序导致结果不一致）。

---

### 3.5 新增：单图处理函数（并发核心单元）

必须新增并锁死“并发最小单元”的抽象（概念约束）：

```text
ProcessSingleImage(ImagePath) → ImageProcessResult
```

要求：

- **无状态**：不得依赖/修改共享可变状态
- **可并发执行**：线程安全，适配 `SemaphoreSlim` 限流并发
- **可单元测试**：输入（路径与依赖抽象）可被替换/模拟，输出确定
- **不依赖 UI**：不出现 WPF 类型或 UI 线程假设

说明：

- 该函数位于 Application 的“并发执行单元”定义中，但其内部会调用：
  - Infrastructure：图片解码/ROI 裁剪/ZXing 识别（返回原始 `List<string>`）
  - Application：多码策略归一化（取第一个）与流程级决策
  - Core：仅处理单值输入的确定性规则（后续阶段）

---

### 新增：【补丁 5】并发异常隔离（ProcessSingleImage 异常收敛规则，强制）

在单图处理过程中，任何异常（解码失败 / ZXing 异常 / ROI 异常等）必须：

- **不得向外抛出**（强制）
- 必须收敛为结构化输出（强制）：
  - `ImageProcessResult.IsUnreadable = true`
  - `Fields` 为空或部分为空（按既定字段分类规则处理）

说明（强制目的）：

- 防止 `Task.WhenAll` 因单个异常导致整个批处理失败

---

### 3.6 新增：ImageProcessResult 结构语义（并发单元输出契约）

> 目的：统一 `ProcessSingleImage` 的返回结构，确保后续匹配、导出、UI 展示可以稳定对接。

`ImageProcessResult` 必须包含：

- **`ImageName`**
  - 语义：图片文件名
- **`Fields`**
  - 语义：模板字段名 → 识别结果（可能为空）
  - 类型约束：`Dictionary<string, string?>`
  - 约束：key = 模板字段名（如 `SN / QR1 / ...`），禁止 key 使用 Excel 列名
- **`RawValues`（可选）**
  - 语义：原始识别结果（多码列表）
  - 类型约束：`List<string>`
  - 规则：仅用于调试/问题定位，不参与 Core 逻辑
- **`IsUnreadable`**
  - 语义：是否整图不可识别（例如 SN 未识别或 ROI 无效导致无法识别）

结构约束（强制）：

- Core 层只使用 `Fields`（不得读取/依赖 `RawValues`）
- Application 决定是否保留 `RawValues`（可按 Debug 开关/配置决定，但不得影响业务结果）
- 禁止使用非结构化数据（如 `object / dynamic`）承载识别结果

---

### 新增：【补丁 6】重复检测输入来源（防止误用 Excel）

#### 强制：DuplicateEngine 输入来源锁死

- 重复检测必须基于：**图片识别结果**（`ImageProcessResult.Fields["SN"]`）
- 禁止（强制）：
  - 基于 Excel 数据做重复检测
  - 在识别过程中实时检测（必须在全部图片处理完成后统一统计）

---

### 新增：常量与配置（强制，禁止 magic number）

> 插入位置要求：并发章节后。目的：避免实现阶段散落“魔法数字/字符串”，并保证 Core/Application 的可测试性与一致性。

必须集中定义（至少包含）：

- **最大并发数策略**：CPU 核心数 - 1（最小 1）
- **支持图片格式白名单**：`jpg / png / bmp`
- **ROI 最小有效尺寸策略（如需）**
  - 约束：宽/高为 0 的情况必须判定为 `UNREADABLE`
  - 若引入“最小阈值”（例如最小宽高像素）也必须集中定义，禁止散落在流程代码中
- **预览最大图片尺寸（UI）**
  - 目的：防止预览渲染造成 UI 卡顿
  - 约束：属于 Presentation 的显示策略，但同样必须集中定义

位置建议（强化）：

- Application / Core 中使用 `Constants` 或 `Options`（强类型配置）
- 约束：Core 使用的常量不依赖 UI；Presentation 的显示类常量不渗透到 Core

## 4. 跨层数据流转（输入 → 处理 → 输出）

### 4.1 输入（文件）

- Excel：`.xlsx`（ClosedXML 读取，**全部按字符串读取**）
- 图片：文件夹导入（`jpg/png/bmp`）
- 模板：JSON（字段 + ROI 相对比例坐标）
- 字段映射：用户选择（模板字段 ↔ Excel 表头列名），可保存为 JSON 复用

### 4.2 典型调用链（数据形态随层次变化）

- **Presentation**
  - 收集用户选择与路径，组装 `AuditRequest`
  - 展示 `AuditResult`（DataGrid 行、汇总统计、预览对照）

- **Application**
  - 调用 Infrastructure 读取 Excel/模板/图片路径
  - 将外部数据转换为 Core 可处理的纯模型
  - 编排阶段顺序与并发
  - 汇总 Core 输出并生成 `AuditResult`
  - 协调 Infrastructure 执行导出（导出失败不丢结果，支持重试）

- **Core**
  - 执行确定性规则：ROI 换算与 Clamp、匹配/比对（Trim 完全比较）、重复检测（仅 SN）、错误分类（NOT_FOUND/MISMATCH/DUPLICATE/UNREADABLE）

- **Infrastructure**
  - ZXing 解码：提供“原始识别输出”（可为空/多码），不做业务判断
  - Excel：读/写与预检查报告导出（写入失败返回可展示错误）
  - 文件系统：输出目录时间戳策略、错误图片复制与分类
  - 图片处理：解码、获取尺寸、裁剪 ROI（解码失败统一上报给上层归类）

---

### 4.3 新增：ROI 越界与无效裁剪处理策略

- ROI 坐标使用相对比例换算为像素坐标后，必须：
  - **自动 Clamp 到图片范围内**（避免越界异常）
- **新增：无效 ROI 判定**
  - 若 Clamp 后裁剪区域无效（宽或高为 0），则该字段（若为 SN 字段则整图）应判定为 `UNREADABLE`
  - 该规则确保不同分辨率/模板轻微偏差下系统不崩溃且结果可解释

---

### 4.4 新增：结果顺序稳定性（输出确定性）

- 并发执行后，任务完成顺序不保证与输入一致。
- 为保证 UI 展示与报告输出可复现，最终输出必须稳定（锁死一种策略）：
  - **策略 A：按输入枚举顺序回填输出**（推荐，最贴近用户导入顺序）
  - **或 策略 B：按文件名排序后输出**（稳定且可解释）
- V1 必须选定并固定一种策略，禁止在 UI 侧“临时排序”造成结果与导出不一致。

---

### 新增：【补丁 4】图片枚举与输入稳定性（防止顺序不一致）

#### 新增：输入图片顺序锁死（强制）

- 在进入并发处理前，必须对图片路径做一次**稳定排序**
  - 推荐：按文件名排序（升序）

说明（强制）：

- 这是“结果顺序稳定策略 A/B”之前的基础保障
- 防止不同文件系统枚举顺序导致结果漂移

---

## 5. 错误表达策略（领域枚举 + 显示映射）

### 5.1 领域错误枚举（固定）

- `NOT_FOUND`：识别出的 SN 不在 Excel 中
- `MISMATCH`：字段值与 Excel 值不一致（Trim 后完全比较）
- `DUPLICATE`：批次内 SN 重复
- `UNREADABLE`：识别失败（SN 失败则整图 UNREADABLE；非主键字段失败仅字段级 UNREADABLE）

### 5.2 UI 状态（行级）与错误类型（细分）分离

- 行级：`PASS / FAIL`
- 细分：上述 `ErrorType`
- 映射规则锁死：`NONE → PASS`，其余任一错误 → `FAIL`（V1 不引入 WARN）

### 5.3 字符串集中管理（强制）

- 所有 UI 文案、提示信息、报告 Sheet 名/列名、错误类型显示名都进入统一 `Strings` 管理（中文优先）。
- 测试断言应以 `ErrorType / PASS-FAIL` 为主，字符串仅用于展示，避免测试被文案变更破坏。

---

### 强化：Strings 分层结构（强制，防止后期混乱）

必须分为以下命名空间（或等价结构，但语义必须一致）：

- `Strings.UI.*`：界面展示（按钮文本、空状态、常规提示）
- `Strings.Error.*`：错误提示（Excel 校验阻断、导出失败提示等）
- `Strings.Report.*`：Excel 导出（Sheet 名、列名、报告标题等）
- `Strings.Stage.*`：阶段名称（用于 `AuditStage` → 展示文案映射）

强制规则：

- 禁止直接写 `"xxx"` 字符串
- 所有 `StageResult.Message` 必须来自 `Strings`

---

## 6. 新增：进度回调机制（UI 稳定性关键）

### 6.1 模式（强制）

- 使用 `IProgress<T>` 模式做进度上报与订阅
- **新增：进度模型 `ProgressInfo`（概念结构）**必须包含：
  - `Current`：当前完成数量（例如已处理图片数）
  - `Total`：总数量（例如图片总数）
  - `Stage`：当前阶段（**必须枚举化**，见 6.4）
  - `Message`：可展示信息（例如当前图片名、阶段提示）

### 6.2 分层职责（锁死）

- **Application**
  - 负责在关键阶段与循环点上报 `ProgressInfo`
  - 负责保证上报频率可控（避免 UI 高频刷新卡顿）

- **Presentation（UI）**
  - 只订阅 `IProgress<ProgressInfo>` 回调并更新 ViewModel 状态
  - 禁止：UI 主动轮询/拉取进度；禁止跨线程直接操作 UI 控件

### 6.3 线程安全要求

- 禁止在后台线程直接修改 UI 控件或 ObservableCollection
- UI 更新必须通过 ViewModel 的绑定路径完成（由 WPF 同步上下文/调度机制保障线程安全）

---

### 6.4 新增：ProgressInfo.Stage 枚举化约束（禁止字符串）

为消除歧义并防止实现发散，`ProgressInfo.Stage` 必须使用枚举类型（建议命名：`AuditStage`），禁止使用自由字符串。

**新增：建议枚举值（必须写入实现，不得运行时动态拼接）**

- `ExcelLoading`
- `ExcelValidating`
- `TemplateLoading`
- `ImageProcessing`
- `Matching`
- `Comparing`
- `Deduplicating`
- `Exporting`

约束（强制）：

- UI 仅根据该枚举做展示逻辑（阶段显示文案来自 `Strings` 映射）
- 禁止在运行时拼接/传递 Stage 字符串作为状态源

---

### 新增：【补丁 9】Progress 精度控制（防止 UI 卡顿）

在 `ImageProcessing` 阶段，进度上报频率不要求“每张图片都上报”。允许采用节流策略（建议但推荐实现）：

- 每 N 张上报一次（例如 5 / 10）
- 或基于时间节流（例如 100ms）

约束（强制意图）：

- 上报频率属于 Application 的责任（见 6.2），UI 仅订阅
- 禁止通过 UI 侧轮询来“弥补”上报频率

---

## 新增：取消机制（Cancellation 设计，强制）

> 插入位置要求：Cancellation → 第 6 章之后。目标：支持用户取消且不影响 UI 稳定性，并保留已完成的部分结果用于展示与导出。

### 新增：Cancellation 规则（强制）

- **Application 层**
  - 每个阶段开始前必须检查取消请求（语义约束：发现取消则不进入下一阶段）
  - 并发任务必须传递同一个 `CancellationToken`

- **并发阶段（图片处理）**
  - 每个并发任务必须响应 `CancellationToken`
  - 被取消的任务不得写入不完整数据到 `AuditResult.Items`
    - 语义约束：要么不写入；要么写入“明确标记为取消/未处理”的结构化结果（实现期二选一，但必须全局一致）

- **UI 行为（Presentation）**
  - 用户可点击“取消”
  - UI 不阻塞
  - 已完成结果可展示（DataGrid 保留已处理行；汇总统计体现“已完成部分”）

取消结果语义（强化）：

- `AuditResult.Meta` 必须体现取消状态（例如 Cancelled 标记）
- 导出仍可对“已完成部分结果”执行（导出不触发重跑）

---

### 强化：阶段定义“枚举统一源”（避免分散）

- Pipeline 阶段顺序必须来源于：**唯一枚举定义 + 顺序约束**
- 禁止：
  - 在实现中写死阶段顺序字符串
  - UI 自定义阶段顺序或自行解释阶段含义
- 约束：
  - `AuditStage` 为唯一阶段源
  - UI 阶段文案通过 `Strings.Stage.*` 映射得到（见字符串结构强化）

---

## 7. 新增：导出失败策略（避免用户重跑）

### 7.1 结果数据来源（锁死）

- `AuditResult` 必须在内存中持有完整审核结果（行结果、明细、统计、元信息）。
- **导出仅是持久化行为**：把内存中的 `AuditResult` 写入磁盘（报告 + 错误图片）。

---

### 新增：【补丁 8】导出输入来源锁死（防止“二次计算”）

导出阶段只能使用：**内存中的 `AuditResult`（当前运行结果容器）**。

禁止（强制）：

- 重新读取 Excel
- 重新识别图片
- 重新执行匹配 / 比对 / 重复检测

### 7.2 导出失败后的行为（锁死）

- 导出失败（例如文件占用/写入失败）时：
  - **不丢失结果**：内存中的 `AuditResult` 保持不变
  - **可重复导出**：允许用户在不重新执行 `RunAudit` 的情况下反复点击导出重试
  - **不重新执行 RunAudit**：禁止为了导出而触发重新识别/重新匹配（避免无谓耗时与结果漂移）

---

### 7.3 新增：轻量阶段追踪 StageTrace（推荐）

目标：提供最小可追溯能力（调试/问题复盘），但不引入完整日志系统。

**新增：AuditResult 可选字段 `StageTrace`（阶段执行记录）**

每条记录包含：

- `StageName`
- `StartTime`
- `EndTime`
- `Duration`
- `IsSuccess`

约束：

- 仅用于调试/问题复盘展示
- 不参与业务逻辑判断
- 不需要复杂日志系统

---

# 新增：测试策略落地（TDD 具体化，强制）

> 插入位置要求：测试策略 → Phase 之前。目的：把“必须 TDD”落到可执行的测试分层与清单，避免实现期只测 happy path 或忽略并发确定性。

## 新增：测试分层（强制）

### 强化：Core 层（关键规则必须覆盖，目标 100%）

- ROI Clamp（越界裁剪、无效 ROI 判定 → `UNREADABLE`）
- Trim 比较（前后空格处理，完全字符串比较）
- Error 分类（`NOT_FOUND / MISMATCH / DUPLICATE / UNREADABLE` 的触发条件）
- Duplicate 检测（批次内仅 SN，统一统计，不依赖执行顺序）

### 新增：Application 层（流程测试）

- 正常流程（Happy Path）
- Excel 校验中断（SN 重复、SN 为空）
- 模板失败中断（模板不可读/解析失败）
- 部分图片 `UNREADABLE`（单图失败不中断）
- 导出失败可重试（不丢失 `AuditResult`，不重跑 `RunAudit`）
- 取消流程（CancellationToken）：返回部分结果且 Meta 标记 Cancelled（不向 UI 抛异常）

### 新增：并发测试（必须）

- 多线程结果一致性：同一输入重复执行多次，输出统计与错误分类一致
- 顺序稳定性验证：并发完成顺序不一致时，最终输出仍按“锁死的稳定策略”一致
- DTO 线程安全约束验证：并发阶段不共享 DTO 实例引用、无跨线程修改同一实例

# 开发计划（Phase 结构）

> 新增：本节用于替代 Day1~Day7，以工程阶段（Phase）拆分交付，便于评审与验收。

## Phase 0：工程初始化（基础骨架）

**目标**

- 建立四层结构（Presentation / Application / Core / Infrastructure）
- 定义核心 DTO（概念与字段形态固定）：
  - `AuditRequest`
  - `AuditResult`
  - `ImageProcessResult`
- 搭建空 `RunAudit` 框架（仅步骤占位与结果结构，不含业务逻辑）

**输出**

- 项目结构清晰
- 可编译通过
- 不包含业务逻辑

## Phase 1：数据层与前置校验

**目标**

- Excel 读取（ClosedXML）
- 字段映射机制（模板字段 ↔ Excel 表头列名，可保存复用）
- SN 唯一性校验
- SN 非空校验（含 Trim 后为空）
- 预检查报告导出（Excel预检查报告.xlsx）
- Pipeline 中断机制落地为“返回结果”（禁止异常控制正常流程）

**要求**

- 全部按字符串读取
- Trim 处理参与比对前的规范化
- 校验失败可中断流程，且 UI 可展示前 N 条样例数据并支持导出预检查报告

## Phase 2：识别能力构建

**目标**

- ZXing 封装（识别服务）
- 图片加载（支持 jpg/png/bmp）
- ROI 裁剪（比例坐标换算 + Clamp）
- 单图处理函数抽象明确：`ProcessSingleImage(ImagePath) → ImageProcessResult`

**要求**

- Infrastructure 仅输出 ZXing 原始结果（`List<string>`）
- Application 决策多码策略（取第一个），并输出标准化单值识别结果
- ROI 无效（宽/高为 0）必须判定为 `UNREADABLE`
- 不做业务判断（仅识别与结构化输出）

## Phase 3：核心业务逻辑（Core 层）

**目标**

- MatchEngine（SN 匹配规则支撑）
- CompareEngine（字段比对：Trim 后字符串完全比较）
- DuplicateEngine（重复检测：仅 SN，统一统计）
- Error 分类逻辑（NOT_FOUND/MISMATCH/DUPLICATE/UNREADABLE）

**要求**

- 纯逻辑、无 IO、无 UI 依赖
- 可单测（TDD）：核心规则覆盖完整
- Core 只接受单值输入，不承担“多码取第一个”等流程决策

---

### 新增：Phase 3 → Phase 4 进入约束（强制门禁）

- **必须满足**：Phase 3（Core 层）完成核心规则能力，并完成对应的**单元测试（TDD）覆盖**与稳定性确认
- **才允许进入**：Phase 4（Application 流程整合）
- 目的：防止在流程整合期“边写流程边改规则”导致返工与分层污染

## Phase 4：流程整合（Application 层）

**目标**

- 实现 `RunAudit` 完整 Pipeline（串联 Phase1~3）
- 实现中断机制（StageResult/AuditResult 返回式中断）
- 并发控制（SemaphoreSlim，CPU-1）
- 进度回调（`IProgress<ProgressInfo>`：Current/Total/Stage/Message）
- 结果顺序稳定策略落地（按输入顺序回填或按文件名排序，二选一锁死）

**要求**

- 单入口 `RunAudit`
- 阶段清晰、可追溯
- 可集成测试（Happy path + 关键中断/异常分支）

---

### 新增：【补丁 10】Phase 4 最小可运行闭环（验收标准，强制）

Phase 4 完成时必须满足（用于验收，防止过度设计或被 UI 依赖阻塞）：

- 能跑通完整 `RunAudit`（单入口）
- 至少支持最小数据集：
  - 1 个模板字段：`SN`
  - 1 张图片
  - 1 行 Excel
- 能输出：
  - 行级：`PASS / FAIL`
  - 错误类型：`NOT_FOUND / MISMATCH / UNREADABLE / DUPLICATE`

说明（强制）：

- 该验收标准优先于“UI 完整接入”，用于确保流程与规则先闭环可测

## Phase 5：UI 层（WPF + MVVM）

**目标**

- 文件导入（Excel / 图片文件夹 / 模板）
- 字段映射 UI
- 审核触发（命令调用 Application）
- 进度显示（订阅 `IProgress<ProgressInfo>`）
- 结果展示（DataGrid：行高亮、虚拟化、稳定排序）
- Quick Preview（选中行刷新预览、双击大图预览并显示“识别 vs 期望”对照）

**要求**

- MVVM 规范，无业务逻辑
- 禁止 code-behind 控制业务与流程
- UI 只订阅进度与结果，不主动拉取

## Phase 6：结果输出与收尾

**目标**

- 报告导出（Excel：元信息/总览/异常明细/重复/未识别）
- 错误图片导出（按 error/duplicate、error/not_found、error/unreadable 分类）
- 输出目录策略（时间戳文件夹，避免覆盖）
- 导出失败策略（保留内存 `AuditResult`，允许重复导出，不重跑审核）

**要求**

- 导出失败可重试
- 不影响已有结果（不清空、不重跑）
